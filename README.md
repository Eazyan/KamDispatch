# Зимний мониторинг Камчатки

Самостоятельный сервис для проверки гипотезы «камера помогает раньше определить, какой участок проверить». Прогноз предупреждает заранее, наблюдения по камерам формируют оперативные сигналы, утренняя сводка собирает события и решения. Пользователь отмечает своё решение в карточке сигнала.

## Быстрый запуск

[API обращений жителей](docs/CITIZENS_API.md) · [Журнал разработки](docs/CITIZENS_LOG.md)

Нужны запущенный Docker Engine с Compose, Python 3 и Bash. На чистой копии из папки компонента выполните:

```bash
./bootstrap.sh
```

Команда создаёт локальный `.env`, генерирует пароль PostgreSQL, подготавливает четыре синтетических кадра и запускает приложение. Откройте [локальный дашборд](http://127.0.0.1:8080). На чистом компьютере для сборки образов нужен доступ к реестрам. В демо приложение использует локальные кадры и контрольный прогноз. Ожидаемый результат — один срочный сигнал и одно предупреждение.

Для запуска со свежими кадрами на чистой копии используйте `./bootstrap.sh --preview`. Для анализа кадров задайте в `.env` адрес сервиса Weather VLM в `MODEL_URL` и его ключ в `MODEL_TOKEN`, если сервис требует авторизацию. Для API с `/v2/scene` используйте `MODEL_CONTRACT=scene_v2`. Существующий `.env` сохраняется, поэтому для переключения ранее запущенного демо измените в нём `MONITOR_MODE=preview` и снова запустите `./bootstrap.sh`. Для реального прогноза заполните `OPENWEATHER_KEY`. Для проверки своей серии подготовьте её через `fixtures/prepare_demo.py`.

## Компоненты

| Компонент | Обязанность |
| --- | --- |
| React + TypeScript | Сигналы, кадры, прогноз, карта подтверждённых точек, решения и журнал доставки |
| FastAPI | Версионированный API, проверка токенов, разграничение прав, аудит и выдача медиа |
| Обработчик | Сбор камер HLS/JPEG, вызов Weather VLM, правила сигналов, OpenWeather, SMTP и сводки |
| PostgreSQL | Миграции, наблюдения, эпизоды, прогнозы, решения и долговечные очереди |
| Медиа | Локальный том или S3-совместимое хранилище |
| Weather VLM | Отдельный GPU-сервис. Контракт `/v1/scene` описывает наблюдаемые признаки |

Сильный снегопад со сниженной видимостью на дорожной камере становится срочным сигналом после двух свежих подтверждений. Для обычного снегопада требуются три. Снимки с тротуара или погодного ракурса не поднимают приоритет дорожного участка. Зафиксированная оператором реакция хранится независимо от физического окончания эпизода.

Состояние события и запись доставки создаются в одной транзакции. Повторный запуск не создаёт второе письмо с тем же ключом. При неопределённом результате SMTP письмо остаётся в журнале со статусом неопределённой доставки. Время хранится в UTC, сводка и показ в интерфейсе используют `Asia/Kamchatka`.

## Закрытый пилот

1. Разверните GPU API с `POST /v1/scene` на выделенном endpoint и сравните ответы на четырёх контрольных кадрах. `POST /v1/snow` сохраняет поддержку прежних полей `image` и `images`. Файлы и инструкция GPU-сервиса находятся в [cameras](cameras) и [документации Ubuntu](docs/WEATHER_VLM_UBUNTU.md). Согласуйте переключение с владельцем действующего API.
2. Определите реальные ракурсы и их дорожную привязку в `monitoring/cameras.json`. Стартовая конфигурация включает Завойко как дорожную камеру и Чехова как погодную до проверки ракурса. Согласованные координаты задаются как `[долгота, широта]`. Для карты по умолчанию используются публичные плитки OSM при наличии подтверждённых точек.
3. Перед API устройте HTTPS-вход с OIDC и проксированием Bearer-токена в `Authorization` для HTML, API и кадров. Для браузерного входа шлюз должен обрабатывать OIDC-сессию и сам выставлять заголовок после проверки. API проверяет RS256, issuer, audience и срок токена; роли сопоставляются с настроенными значениями `sub`. Хостовый порт Compose привязан к loopback.
4. Задайте `MONITOR_MODE=live`, HTTPS-адреса в `PUBLIC_URL` и `MODEL_URL`, параметры OIDC в файле окружения. Настройте ключ OpenWeather One Call и TLS SMTP. Сначала проверьте канал на тестовом адресате, затем задайте согласованный список `MAIL_TO`. При пустом списке сообщения сохраняются в журнале.
5. Перед открытием пилота проверьте доступность и свежесть камер, результат инференса, получение трёх видов письма, сохранение очереди после перезапуска и восстановление копии PostgreSQL и медиа. Настройте ротацию медиа и журналов по условиям пилота. В Compose база и медиа находятся на одном сервере, резервные копии должны храниться отдельно. Для закрытого пилота один экземпляр обработчика владеет планировщиком через advisory lock.

Адаптер использует [OpenWeather One Call 3.0](https://openweathermap.org/api/one-call-3). Стартовый порог вероятности задаётся через `SNOW_PROBABILITY`. Сводка выпускается в 07:00 по Камчатке и повторно не создаётся для той же даты.

## Проверка и воспроизведение

```bash
npm --prefix web ci
npm --prefix web run build
python3 -m venv .venv
.venv/bin/pip install -r requirements-test.txt
TEST_DATABASE_URL='postgresql://user:password@127.0.0.1:5432/test' .venv/bin/python -m pytest -q
```

Используйте временную базу для интеграционных тестов. Тесты создают отдельные запуски, проверяют PostgreSQL, HTTP, матрицу решений, повтор запроса и SMTP на локальном приёмнике.

В режиме `replay` загрузите манифест с временами и наблюдениями командой `python -m monitoring.replay /path/to/manifest.json --id scenario-a`. Затем откройте дашборд с `?run=scenario-a`. Структура манифеста видна в `runtime/demo/manifest.json` после подготовки демо. Каждое наблюдение применяется к правилам в порядке времени съёмки.

### Автобусные проезды

На главной карте слой «Автобусы» включён при открытии. Нажмите метку, чтобы увидеть маршрут и время GPS. В `preview` карта показывает свежие позиции РНИС, в `/demo` — четыре метки с пометкой «Имитация» на Тельмана и Карьерной. В `/demo#dispatch` доступен выбор сценария в блоке «Участки для проверки». Генератор записывает входы в `bus-input.json` и причины событий в отдельный `bus-truth.json`. Команда `python3 -m monitoring.bus_demo` воспроизводит сравнение окон без сети и базы.

| Окно, мин | Медиана задержки, мин | Пропущенные эпизоды из 7 | Ложные подсказки |
| ---: | ---: | ---: | ---: |
| 5 | 5,0 | 6 | 0 |
| 10 | 9,5 | 3 | 0 |
| 20 | 9,5 | 2 | 0 |

При интервале рейсов 5 минут окно 10 минут дало подсказку через 9,5 минуты от начала события. При интервале 10 минут сработало окно 20 минут, задержка составила 14,5 минуты. При интервалах 20 и 40 минут во всех проверенных окнах получился пропуск. Задержка доставки GPS может вытолкнуть первый проезд из окна, если окно равно интервалу рейсов. Результаты относятся к сценариям имитации.

В `preview` теневой сбор включён по умолчанию. `BUS_RNIS_ENABLED=0` отключает его, а `BUS_RNIS_ENABLED=1` включает в `live`. Адаптер читает публичный запрос [карты РНИС](https://bus.kamgov.ru/) каждые 30 секунд. Сохраняются только записи с типом `bus` и свежим временем измерения. Исходные идентификаторы хешируются, госномера и коды устройств отбрасываются. GPS-точки хранятся 7 дней, проезды — 28 дней. После накопления хотя бы одного полного 10-минутного окна команда ниже покажет покрытие на дорогах из пилотной геометрии, включая пустые окна.

```bash
docker compose exec api python -m monitoring.bus_worker --scan
```

Выберите до трёх коридоров по доле окон с двумя машинами. Для проверки по камере нужен подтверждённый обзор того же участка. Укажите JSON-файл через `BUS_SECTIONS_FILE` и смонтируйте его по указанному пути в API и worker. Каждый элемент массива содержит `id`, `name`, `coordinates` в порядке долгота/широта, доли длины `entry_fraction` и `exit_fraction` между остановками, ключ участка диспетчерской `location_key` и `publish`. Ключ для камеры с настроенным участком имеет вид `section:<section_id>`, для обращения по выбранной дороге — `road:<id>`. Пустой массив `publish` оставляет участок в теневом режиме. Команда выше без `--scan` покажет покрытие по сохранённым проездам настроенных участков.

Сверьте время подсказок с имеющимися кадрами, обращениями и результатами проверок. В карточке обращения отмечайте «В обращении указано, что проезд затруднён» только при явном указании на проезд. Считайте дневные и ночные смены раздельно. После 10 подтверждённых эпизодов и 10 смен добавьте `day` (06:00–22:00) или `night` в `publish`, если медианный выигрыш на общих эпизодах достиг 5 минут либо найдены два дополнительных подтверждённых эпизода, и появилось максимум одно дополнительное ложное срабатывание на 10 смен. Первый запуск в другом режиме имеет собственную историю проездов и набирает базу отдельно.

## Реальные данные и демо на одном Mac

Для локального просмотра реальных данных установите `MONITOR_MODE=preview`. Основная страница показывает реальные камеры, а [демо](http://127.0.0.1:8080/demo) использует свой набор записей и медиа. Локальный API Compose доступен по loopback. В этом режиме сообщения попадают в журнал. Для рабочего доступа с рассылкой используется отдельный режим `live` с HTTPS и OIDC.

Укажите адрес своего Weather VLM в `MODEL_URL`. Для API с `/v2/scene` задайте `MODEL_CONTRACT=scene_v2`. Подробные признаки поступают из `/v2/scene`. Если модель вернула результат вне схемы, обработчик пробует `/v1/scene`. Для уточнения падающего снега используется `/v1/snow`. Для V2 в карточке «Видимость по кадру» показывает качество обзора, если отдельной оценки видимости в ответе нет. Заключение формируется по-русски из валидированных полей. Укажите `OPENWEATHER_KEY` для получения реального прогноза.

В журнале обработчика можно проследить кадр по полю `frame`.

```bash
docker compose logs -f --since=15m worker
```

Событие `camera_source` показывает причину сбоя источника, например `http_403`, `invalid_jpeg` или `ffmpeg_timeout`. События `camera_capture`, `camera_model` и `camera_analysis` показывают сохранение кадра, вызванные маршруты модели, длительность анализа, причину пропуска и признаки без оценки.

PostgreSQL хранит времена, события, решения и очередь. Для фотографий можно использовать локальный том или закрытый S3. В локальном Compose доступно объектное хранилище SeaweedFS. Задайте `S3_BUCKET=kamchatka-frames`, `S3_ENDPOINT=http://object-store:8333`, случайные `AWS_ACCESS_KEY_ID` и `AWS_SECRET_ACCESS_KEY` в `.env`. S3 доступен только в сети Compose. Демо продолжает читать файлы из своего тома.

```bash
docker compose -f compose.yaml -f compose.s3.yaml build api
docker compose -f compose.yaml -f compose.s3.yaml up -d --no-build
```

Регулярно копируйте PostgreSQL и том объектного хранилища. Копия базы содержит ссылки на кадры и восстанавливается вместе с самими объектами. Для рабочего развёртывания можно указать внешний S3-совместимый адрес и выдать приложению ключ с доступом к выделенному бакету.

## Прогноз и работа с сигналами

### Экспериментальный прогноз по дорожным отрезкам

В `demo` на карте «Обстановка» доступен контрольный сценарий с пятью отрезками в Петропавловске-Камчатском. Он рассчитан на геометрии OpenStreetMap для условного снегопада с ветром 315° и скоростью 12 м/с. В `preview` и `live` задайте базовый адрес сервиса симуляции в `.env`, например `SNOW_SIM_URL=https://snow-sim.example.org`. Для сервиса, работающего на хосте Docker Desktop, можно использовать `http://host.docker.internal:8000`. Примените миграцию и настройки командой `docker compose up -d --build api worker`.

Контейнеру `worker` нужен доступ к сервису с `POST /api/snow`, локальным снимком зданий Петропавловска и подключением к Open-Meteo. CAMCHATKA запрашивает трёхчасовой расчёт для тайлов каждые 30 минут. Сервис симуляции развёртывается отдельно. Локальная копия `kamcha-snow-sim-main/` исключена из Git и контекста сборки Docker.

Пилотные отрезки заданы в [`monitoring/snow_segments.json`](monitoring/snow_segments.json). `coordinates` — линия в WGS 84 в порядке долгота, широта. `osm_way` служит ссылкой на источник геометрии. `camera_id` можно добавить после проверки видимости отрезка дорожной камерой. Для отдельной конфигурации задайте `SNOW_SEGMENTS_FILE` и смонтируйте файл по этому пути в контейнер `worker`.

Кандидат на проверку — отрезок с расчётным избытком свежего снега от 1 см в верхнем квартиле выборки вдоль его оси. Это стартовый порог пилота. В деталях отрезка можно включить тепловой слой расчётного избытка от 1 см. Пропуски, ошибки сервиса и устаревшие результаты показываются отдельно. Рабочий прогноз и использованная погода сохраняются в `snow_forecasts`. Результат предназначен для проверки участка диспетчером. Камеры и записи объездов нужны для оценки точности на местности.

### Городской режим Петропавловска-Камчатского

В режиме `preview` или `live` добавьте `compose.snow.yaml`. `SNOW_SIM_SOURCE` указывает на отдельный каталог исходников симулятора с `snowmap/`, `kernels/` и `data/petropavlovsk-buildings.json`. Docker использует его как контекст сборки отдельного образа симулятора.

```bash
export SNOW_SIM_SOURCE=/absolute/path/to/kamcha-snow-sim
docker compose -f compose.yaml -f compose.snow.yaml build api snow-sim
docker compose -f compose.yaml -f compose.snow.yaml up -d --wait api worker snow-city
```

Городская окраска доступна на главном экране «Обстановка». Отдельный `snow-city` запрашивает один пакет погоды Open-Meteo на все зоны, рассчитывает трёхчасовое окно примерно каждые 30 минут и публикует снимок в PostgreSQL. Снимки городского расчёта хранятся сутки. Для коммерческого подключения задайте `SNOW_WEATHER_URL` и `SNOW_WEATHER_KEY` согласно выбранному тарифу. [Условия Open-Meteo](https://open-meteo.com/en/terms)

По умолчанию весь город рассчитывает локальный контейнер `snow-sim`. Для отдельной установки `city_sim` с совместимым API можно указать её внутренний адрес в `SNOW_CITY_REMOTE_URL`. В этом режиме `snow-city` запрашивает расчёт на свежем прогнозе, ждёт завершения по `run_id` и сопоставляет растр с дорожной сетью CAMCHATKA. `snow-sim` досчитывает участки без достаточного покрытия в том же окне.

### Карта Neverrie и экран «Обстановка»

В режиме `preview` или `live` карта Neverrie из `kamcha-snow-sim-Neverrie/` открывается прямо на главном экране. Слева расположены разделы, справа — виджеты по участкам. Срочные проверки и просроченные задания поднимаются в начало списка. Клик по отметке раскрывает карточку, а выбранная карточка подсвечивает участок. Полный журнал сигналов находится в разделе «Камеры». Дорожные слои и детализация отрезков доступны также в разделе «Прогноз».

```bash
export SNOW_SIM_SOURCE="$PWD/kamcha-snow-sim-Neverrie"
docker compose -f compose.yaml -f compose.snow.yaml -f compose.city-3d.yaml build api snow-sim city-api city-web
docker compose -f compose.yaml -f compose.snow.yaml -f compose.city-3d.yaml up -d --wait api worker snow-city city-web
```

При запуске `snow-city` проверяет срок последнего результата и автоматически запрашивает новый, когда свежего снимка нет. Все окна используют опубликованный результат по одному `remote_run_id`. На карте доступны свежий снег, итоговые наносы, объём снега, шкала времени и ветер. Режим «Сценарии модели» открывает полный интерфейс Neverrie для ручных расчётов. При недоступности 3D работает обзорная карта с оценками дорожных отрезков.

`CITY_SIM_PUBLIC_URL` — базовый адрес Neverrie, доступный браузеру. По умолчанию это `http://127.0.0.1:8008/`; порт задаёт `CITY_SIM_PORT`. Для HTTPS-развёртывания укажите HTTPS-адрес и разрешите встраивание с адреса CAMCHATKA в настройках прокси Neverrie. Пакет встраивания монтируется из `city-map/` по пути `/static/ops/`. `CITY_SIM_SOURCE` указывает на каталог оригинального проекта. Результаты Neverrie хранятся в томе `city_sim_state`.

### Поиск и дорожная обстановка

Поиск на карте использует индекс City Sim для улиц, адресов из локального OSM,
камер, автобусов с текущими позициями, обращений, заданий и разделов веба.
Можно искать по части названия и с опечатками. Номер дома ищется точно.

Кнопка «Пробки» показывает интервалы Яндекс Карт на коридорах `graph_v3`.
Сбор ведёт Windows-воркер. Для прямой HTTP-выдачи задайте в локальном
`.env` значение `TRAFFIC_WORKER_URL=http://WINDOWS_HOST:8766` с доступным из
контейнера адресом. Проверьте `GET /health` у источника и `GET /api/v1/traffic`
у KamDispatch. Если используется SSH, настройте адрес по
[инструкции к туннелю](city-sim/docs/TRAFFIC_SSH.md).
Разрывы между наблюдениями дорисовываются вдоль графа и отображаются
приглушённо. Предел — 250 м на именованных улицах и 100 м в остальных случаях. При разных цветах граница проходит по середине разрыва.

Встроенная 3D-карта поворачивается разворотом двух пальцев на сенсорном экране
или на трекпаде Mac в Safari. Движение двумя пальцами вверх или вниз меняет
наклон, щипок меняет масштаб. Компас можно перетаскивать для поворота.

### Демосценарии экрана «Обстановка»

В меню «Демо» доступны «Спокойная смена», «Начало снегопада» и «Уборка в городе». Прямые ссылки с параметрами `?scenario=calm`, `?scenario=snowfall` и `?scenario=response` открывают те же состояния. В этих сценариях используются фиксированные демонстрационные данные для карты, погоды, сигналов и заданий. Редактировать задания можно в обычной диспетчерской и в существующем серверном демо `/demo`.

«Уборка в городе» воспроизводит демонстрационную смену 15 января 2026 года. Встроенная карта запрашивает сохранённую серию январского циклона Neverrie на данных Open-Meteo ECMWF IFS. При отсутствии результата решатель рассчитывает её автоматически. Кнопки «До выезда», «Уборка» и «Приёмка» переключают задачи и время модели. Модель показывает накопление снега без учёта демонстрационных работ.

Обзорная подложка построена скриптом `scripts/build_overview_map.py` из дорожной геометрии OpenStreetMap и рельефа Neverrie. Рельеф произведён с использованием Copernicus WorldDEM-30 © DLR e.V. 2010–2014 и © Airbus Defence and Space GmbH 2014–2018, предоставленного в рамках COPERNICUS Европейским союзом и ESA. Все права защищены.

Граф `monitoring/snow_roads.json.gz` включает автомобильные и служебные дороги OpenStreetMap в муниципальной границе из снимка симулятора. Скрипт `scripts/import_snow_roads.py` принимает региональный PBF, снимок зданий с границей и путь для результата. Импорт запускается в окружении с Osmium, Shapely и доступным для импорта пакетом `snowmap`. [Региональный снимок](https://geo2day.com/russia/far_eastern_federal_district/kamchatka_krai.html) · [Атрибуция OpenStreetMap](https://www.openstreetmap.org/copyright)

### Погодные предупреждения

OpenWeather One Call используется первым. При отказе в доступе сервис запрашивает стандартный прогноз на пять суток с шагом три часа. Карточки прогноза отображают фактический горизонт. Предупреждение формируется отдельно от наблюдений камер и следует настройке `SNOW_PROBABILITY`.

Очередь проверки показывает по одному свежему открытому сигналу на дорожную камеру. Выше стоят срочные сигналы, затем более важные участки и более свежие подтверждения. Вес участка `road_priority` и его объяснение `road_priority_reason` задаются в `monitoring/cameras.json`. Для Завойко основание приоритета — перекрёсток с пешеходным переходом.

Карточка ищет последний сопоставимый кадр до ухудшения за сутки с той же камеры. После выезда оператор может просмотреть и закрепить свежий кадр после работ. Отметки «Подтвердилось», «Ложный сигнал» и «Уже в работе» сохраняются отдельно от решения и видны в сводках.

### Очередь диспетчера

Сводка по районам показывает срочные проблемы без исполнителя и открытые задания с истёкшим сроком. Фильтры по району, приоритету и статусу применяются к списку, а блок «Срочно в других районах» позволяет открыть карточку в соседнем районе из текущего представления.

В открытом задании оператор указывает исполнителя, срок по Камчатке и указания. После выдачи кнопка «Ссылка для исполнителя» позволяет передать отдельную мобильную карточку задания. По ней исполнитель подтверждает получение, начинает работу и передаёт результат. Оператор может внести те же отметки по телефону, вернуть результат на доработку или принять и закрыть задание. Смена исполнителя отзывает старую ссылку и сбрасывает подтверждение. В рабочем развёртывании шлюз должен пропускать страницу `/assignment` и API `/api/v1/crew/` с их собственным ключом доступа. Шлюз передаёт заголовок `Authorization` для API исполнителя без подмены токеном OIDC.

В режиме `live` бригада также получает открытые назначения в разделе «Мои задания» по адресу `/crew`. Задайте `DISPATCH_CREW_SUBJECTS='{"oidc-subject":"Бригада № 1"}'` как соответствие учётных записей OIDC названиям исполнителей. Эти названия появляются в подсказках при назначении. Страница `/crew` и API `/api/v1/dispatch/crew-inbox` используют обычный шлюз OIDC.

В карточке обращения кнопка «Связать с заданием» позволяет выбрать открытое задание в том же районе, даже если адрес и отметка на карте записаны по-разному. Если по итогам проверки нужна уборка, оператор создаёт её из результата проверки. Обращения и дорожные сигналы переносятся в новое задание, а результат проверки остаётся в истории. При приёмке связанная заявка закрывается с указанным итогом. Закрытые задания и результаты доступны в архиве.

В разделе «Диспетчерская» выберите район или оставьте «Все районы». Кнопка «Добавить обращение» открывает форму регистрации. Очередь объединяет актуальные дорожные сигналы и обращения жителей по участку и типу проблемы. Через «Открыть» оператор открывает кадры отдельных камер, смотрит обращения и создаёт одно открытое задание на проверку или уборку по проблеме. При появлении новых источников оператор привязывает их к заданию из той же карточки. Задание и привязанные источники остаются в очереди, когда сигнал камеры завершается. На этом этапе задание хранится в CAMCHATKA в статусе «Создано».

В `monitoring/cameras.json` укажите `district`, если он отличается от `area`. Дорожным камерам одного участка задайте одинаковые `section_id`, `section_name` и район. Камера без участка образует отдельную точку. Фильтр районов обновляется по всем камерам и обращениям. Для обращения введите улицу и ближайший дом или отметьте место на карте. Дорожный слой Петропавловска-Камчатского позволяет выбрать готовый отрезок. В любой области карты можно вручную отметить начало и конец участка. Адресные записи объединяются при совпадении района, адреса и типа проблемы без учёта регистра и повторяющихся пробелов.

### Проверочная почта

Для локального `preview` доступен изолированный почтовый приёмник:

```bash
docker compose -f compose.yaml -f compose.s3.yaml -f compose.mail-test.yaml build api
docker compose -f compose.yaml -f compose.s3.yaml -f compose.mail-test.yaml up -d --no-build
```

[Почтовый ящик Mailpit](http://127.0.0.1:8025) принимает письма на тестовый адрес `dispatch@example.test`. Реальные получатели настраиваются через `MAIL_TO` и TLS SMTP в режиме `live`. Форматы доставки включают прогнозное предупреждение, оперативный сигнал с JPEG и утреннюю сводку. Демо хранит сообщения в своём журнале.

## Обращения жителей

Запустите `./bootstrap.sh`. Скрипт создаёт локальную конфигурацию при первом запуске и поднимает PostgreSQL, API, обработчик мониторинга и Telegram-бота. Форма открывается по адресу [localhost:8080/citizens/](http://localhost:8080/citizens/). Для подключения Telegram задайте `BOT_TOKEN` в `.env` или в окружении и повторите команду. Внутренний ключ создаётся в `.env` автоматически. Без токена форма работает, а бот завершает запуск без подключения к Telegram. Используйте один экземпляр опроса на токен.

Для подключения MAX добавьте `MAX_BOT_TOKEN` в `.env` и выполните `./bootstrap.sh`. Если задан токен, bootstrap скачивает корневой и промежуточный сертификаты Минцифры с Госуслуг в `runtime/max/ca.pem`. Контейнер подключает их для HTTPS-запросов к MAX и его медиа-серверам. Контейнер `max-bot` запускает один экземпляр бота с длинным опросом MAX. В личном диалоге доступны «Новое обращение», «Мои обращения» и отмена черновика. Фото, описание и геопозиция поступают в общий сервис обращений. Длинный опрос предназначен для разработки и проверки. Для него бот должен быть без активной webhook-подписки. [Создание бота MAX](https://dev.max.ru/docs/chatbots/bots-create) · [Длинный опрос MAX](https://dev.max.ru/docs-api/methods/GET/updates).

#### Роли ботов на тестовом стенде

В личном чате с ботом команда `/role` показывает ID аккаунта и текущую роль. В MAX кнопка «Сменить роль» позволяет переключаться между назначенной ролью и ролью жителя. Укажите нужные ID в `.env` и повторите `./bootstrap.sh`. Пример с условными ID:

```dotenv
DISPATCH_BOT_CREWS='{"telegram:111111111":"Бригада №1"}'
DISPATCH_TELEGRAM_ADMINS=222222222
DISPATCH_MAX_OPERATORS=333333333
```

- Житель без специальной роли отправляет фото, описание и точку. Новая жалоба из Telegram появляется в «Диспетчерской» и в «Обращениях жителей». Диспетчер создаёт из неё задание и назначает «Бригаду №1».
- Участники назначенной бригады получают сообщение о задании в Telegram или MAX. Каждый участник должен заранее открыть личный чат с соответствующим ботом. Задание закрепляется за первым, кто нажмёт «Принять». Он открывает `/jobs`, начинает работу и отправляет фото результата с описанием в подписи. У остальных участников задание исчезает из списка. Если диспетчер возвращает работу, бот сообщает причину только закреплённому участнику и предлагает начать доработку и прислать новое фото. В `DISPATCH_BOT_CREWS` можно также привязать учётную запись MAX с ключом вида `max:444444444`.
- Диспетчер в MAX открывает `/jobs`, отмечает принятие назначенного задания или подтверждает выполненное задание с комментарием. Статус и история общие с веб-диспетчерской. Фото видно перед подтверждением в MAX, в карточке веб-диспетчерской и в архиве.
- Администратор запускает личный диалог Telegram через `/start`, чтобы бот мог отправлять предупреждения. Команда `/warnings` показывает действующие прогнозы. Автоматическая доставка проверяет их раз в минуту и запоминает отправленную версию. Для проверки с прогнозом в режиме `preview` настройте `OPENWEATHER_KEY` и используйте период с действующим предупреждением. Интеграционный тест проверяет доставку на подставной записи прогноза.

Боты работают с текущим запуском сервиса. Для режима `replay` сначала загрузите запись; без неё жалоба остаётся доступна во вкладке «Обращения жителей».


Сводка зон локального режима доступна командой `docker compose run --rm bot python -m monitoring.citizen_bot --zones --min-reports 2`. Для режима `live` передайте токен оператора или наблюдателя через переменную `CITIZEN_STAFF_TOKEN` и опцию `docker compose run --rm -e CITIZEN_STAFF_TOKEN bot …`.

### Переход с предыдущей версии

Остановите старый бот и старую веб-форму перед переносом, сохраните копию SQLite и задайте `BOT_TOKEN` от исходного бота. Telegram требует этот токен для чтения ранее загруженных фото. Выберите режим назначения через настройки KamDispatch. Из корня проекта выполните:

```bash
docker compose run --rm -v "$(realpath ../bot/reports.sqlite3):/tmp/legacy.sqlite3:ro" \
  api python -m monitoring.citizen_import /tmp/legacy.sqlite3
```

Для систем с SELinux можно использовать копию базы и параметр монтирования `:ro,Z`. Импорт сохраняет автора Telegram, адрес, описание, координаты, исходное время и фото. При ошибке вся операция откатывается. Повтор пропускает уже перенесённые записи. После переноса обращения открываются по UUID, указанному в «Моих обращениях». Прежнюю папку можно хранить как архив. SQLite используется только командой переноса.

Контракт и настройка границ районов описаны в [API обращений](docs/CITIZENS_API.md).
