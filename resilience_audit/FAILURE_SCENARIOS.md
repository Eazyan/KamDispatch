# Сценарии и критерии

Все команды отказа направлены в Compose `kamdispatch-resilience`. Новый контур восстановления использует собственные случайно именованные тестовые тома. Сценарии не используют публичные URL. Полные времена и наблюдения сохранены в [TEST_RESULTS.json](TEST_RESULTS.json). По умолчанию каждый сценарий F01–F09 запускается в одном прогоне, отдельный ID запускает только выбранный опыт.

| Опыт | Исходные условия и гипотеза | Механизм и ожидаемое поведение | Фактическое поведение и последствия |
| --- | --- | --- | --- |
| F01 Погода | Есть 6 свежих результатов. При ошибке пользователь видит недоступность либо возраст предыдущих данных. | Подменить ответы на 503, невалидный 200 и 403 с рабочим 2.5. Повторить обычную функцию опроса в worker. | **FAIL.** 503 и невалидный 200 сохраняют все прежние значения. БД видит отказ, панель скрывает статусы. Fallback и новый успешный опрос работают. Диспетчер рискует принять старый прогноз за актуальный. |
| F02 Камеры | 20 свежих синтетических JPEG. Ошибка источника должна быть видна без падения панели. | 503 на всех JPEG, затем восстановление выдачи. | **PASS.** Все 20 получили статус error, затем available. Последние кадры могут служить контекстом с учётом даты. В ходе первого запуска в тесте ошибочно ожидался `ready`, контроль повторён с фактическим статусом `available`. |
| F03 Пробки | Публикация с правильным графом и новым временем. | Сменить хеш графа, затем отдать валидную публикацию двухчасовой давности и вернуть свежую. | **PASS** на контракте API. Несовместимый граф → 503 после окна кэша. Старые сегменты приходят с истёкшим `valid_until`. Цвет на карте нельзя интерпретировать как свежее наблюдение без срока. Точное визуальное переключение цвета при истечении срока не замерялось. |
| F04 Интернет и комбинированный отказ | Приложения на внутренней сети работают через симуляторы. | Одновременно выключить трафик, погоду и камеры. Сохранить основной веб и локальный City Sim. | **PASS** для доступности независимых функций. Трафик 503, камеры error. В панели остались 6 погодных результатов без статусов. Принятие решения без этих источников требует ручного подтверждения. |
| F05 City API | City Sim работоспособен, основной API независим. | Остановить только `city-api`. Проверить обособление отказа и вернуться к 200 после старта. | **PASS** для локализации и восстановления. У API рельефа клиентский таймаут 8 с, у HTML карты и основной панели 200. Статика сама по себе создаёт впечатление доступности расчёта. |
| F06 PostgreSQL | API и City Sim отвечают, есть данные и проверки. | Остановить только PostgreSQL. Панель должна понятным образом показывать деградацию. | **FAIL.** Readiness 503, панель API 500, HTML и City API 200. При старте база вернула прежние прогнозы. |
| F07 Worker | Сохранён heartbeat и загружен прогноз. | Остановить worker, сравнить heartbeat и публичную выдачу, запустить обратно. | **FAIL.** Heartbeat перестал меняться. Общий readiness и панель оставались 200, данных о сбое в публичной выдаче нет. |
| F08 Нагрузка и граница выдачи | Публичный viewer, 20 JPEG-источников. | 36 чтений панели, 6 параллельных клиентов. Проверить, что внутренние маршруты не выставлены публичным шлюзом. | **PASS** для контрольной нагрузки и конфигурации. Публичные страницы обращений и API дорог диспетчера вернули 404. Нагрузочная запись обращений и предел производительности не проверены. |
| F09 Бэкап | Синтетические SQL-данные, SQLite и кадры. | Выгрузить дамп, медиа и SQLite; восстановить в отдельную SQL-базу; проверить схему и целостность. | **PASS.** 21 миграция, восстановлены прогнозы и кадры. SQLite integrity check вернул ok. |
| F10 Потеря узла | Три файла синтетической резервной копии и доступные образы. | Поднять сеть, тома и сервисы с нуля в новом проекте. Открыть восстановленную панель, кадр и карту. | **PASS.** В новых томах открылись панель, 6 прогнозов, JPEG и City API за 18,21 с. Этот опыт не моделирует недоступность Docker Registry или реальную потерю площадки. |

```bash
python3 resilience_audit/tests/chaos.py
python3 resilience_audit/tests/cold_recovery.py
```

Время обнаружения измерено от начала наблюдения после переключения фикстуры или остановки контейнера. Для OpenWeather вызов опроса инициирован вручную. Штатный интервал опроса — 30 мин. Замеры субсекундные для некоторых действий ограничены одним Mac и локальной сетью.
