# Снегоплан

Прототип системы планирования и диспетчеризации снегоуборочной техники для Петропавловска-Камчатского.
Цель — минимизировать «холостой» пробег (перегон без уборки), время и расход топлива, а также
оперативно перестраивать маршруты при поломках и новых заявках.

* **Диспетчер** (`/dispatcher`) — карта, парк машин, метрики «план против базового», события, предложения
  о перепланировании (принимаются автоматически в демо-режиме или вручную).
* **Водитель** (`/driver?v=П-01`) — мобильный экран: текущий участок, подъёмы впереди, кнопки
  «Участок готов» и «Проблема».
* Без внешних тайлов: карта рисуется из собственных данных (OSM), работает офлайн.

## Требования

* Windows 10/11, Python 3.11+ (с «Add to PATH»), Node.js 20+. Git не нужен.
* Интернет нужен только для `setup.bat` и (по желанию) для загрузки OSM в `prepare_data.bat`.

## Установка

1. `setup.bat` — создаёт `backend\.venv`, ставит Python-зависимости и `npm install` во `frontend`.
2. `prepare_data.bat` — скачивает реальные данные OSM (дороги, слои карты, высоты) и строит
   `backend\data\graph.json` и `basemap.geojson`. Если загрузка не удалась — автоматически строится
   синтетический город (офлайн).

## Запуск

* `run.bat` — запускает бэкенд (uvicorn, `0.0.0.0:8000`) и фронтенд (Vite, `0.0.0.0:5173`) в двух окнах
  и открывает `http://localhost:5173/dispatcher`.
* `run_mock.bat` — только фронтенд с встроенной имитацией (`?mock=1`), бэкенд не нужен.
* Вручную: `cd backend && .venv\Scripts\python -m uvicorn app.main:app --port 8000`,
  `cd frontend && npm run dev -- --host`.
* Тесты: `cd backend && .venv\Scripts\python -m pytest`.

## Экран водителя на телефоне

1. Телефон и компьютер в одной Wi-Fi сети.
2. На компьютере выполните `ipconfig`, найдите «IPv4-адрес» (например `192.168.1.25`).
3. На телефоне откройте `http://192.168.1.25:5173/driver?v=П-01` (для другой машины — `v=П-02` и т. д.).
4. Если страница не открывается — разрешите входящие подключения на порт 5173 в брандмауэре Windows
   (при первом запуске Node.js согласитесь на запрос доступа для частных сетей).

## Демо-сценарий

1. Откройте `/dispatcher`. Справа вверху видно сравнение с базовым планом (минус % холостого пробега).
2. Нажмите «Старт» и выберите скорость ×10 — машины поедут по маршрутам.
3. Нажмите «Поломка» и выберите машину: она останавливается, появляется предложение нового плана
   (какие участки кому передаются, изменение пробега и времени окончания).
4. В демо-режиме план применяется автоматически через несколько секунд (обратный отсчёт на карточке);
   можно принять или отклонить вручную.
5. Нажмите «Новая заявка» и укажите улицу на карте — участок добавится в маршрут ближайшей машины.
6. Откройте `/driver?v=П-02`: водитель видит новый участок, может нажать «Участок готов»
   или «Проблема» (поломка, не проехать, застрял, уже почищено, другое) — диспетчер получает событие,
   при «Поломка / Застрял / Не проехать» запускается перепланирование.

## Если что-то не работает

* **Не скачивается OSM** (нет интернета, блокировка Overpass): `prepare_data.bat` сам переключится на
  синтетический город; можно запустить явно: `python -m scripts.prepare_data --synthetic` из `backend`.
  Если `graph.json` отсутствует, бэкенд при старте также использует синтетику (принудительно:
  переменная `SNEGOPLAN_SYNTHETIC=1`).
* **Порт занят** (8000 или 5173): закройте старые окна «Snegoplan backend/frontend» или найдите процесс:
  `netstat -ano | findstr :8000` и `taskkill /PID <pid> /F`. Другой порт бэкенда потребует правки
  `proxy` в `frontend\vite.config.ts`.
* **Не ставятся osmnx/geopandas/rasterio**: они нужны только для загрузки OSM. Для работы с синтетикой
  достаточно `fastapi uvicorn networkx numpy scipy pydantic`.
* **Страница пустая / «нет связи»**: проверьте, что окно бэкенда без ошибок и открыт
  `http://localhost:8000/api/health`. Демо без бэкенда: `run_mock.bat`.
* Кириллица в `.bat`: файлы в UTF-8, используется `chcp 65001`; при «кракозябрах» смените шрифт консоли
  на Consolas/Lucida Console.

```
setup.bat prepare_data.bat run.bat run_mock.bat
backend/
  app/       FastAPI: main.py (приложение), api.py (REST), ws.py (WebSocket + цикл симуляции), config.py
  core/      models.py (pydantic), graph.py (граф улиц, задачи), elevation.py (высоты, уклоны)
  solver/    carp.py (оптимизатор), baseline.py (базовый план), cost.py (модель затрат), metrics.py, trucks.py
  sim/       engine.py (симулятор, события, предложения), events.py (тексты событий)
  scripts/   prepare_data, fetch_osm, fetch_elevation, build_graph, make_synthetic_data
  data/      graph.json, basemap.geojson, кэш высот
  tests/     pytest, синтетический город
frontend/
  src/api/   клиент REST/WS, типы (зеркало models.py)
  src/state/ store.ts (состояние), mock.ts (демо без бэкенда)
  src/pages/ Dispatcher.tsx, Driver.tsx;  src/components, src/map (MapLibre)
```

REST: `/api/state`, `/api/basemap`, `/api/graph/edges`, `/api/sim/control`, `/api/events/{breakdown,request,problem}`,
`/api/proposal/{id}/{apply,reject}`, `/api/tasks/{id}/complete`, `/api/driver/{id}` и др.; WebSocket `/ws`
(сообщения `snapshot`, `event`, `proposal`, `plan`). Время симуляции — секунды от 06:00; `t_start/t_end`
шагов маршрута — абсолютные секунды симуляции.

## Алгоритм (кратко)

Задача — CARP (Capacitated Arc Routing Problem) на ориентированном графе улиц: каждый участок улицы
нужно проехать с уборкой, перегоны между участками минимизируются.

1. Улицы → задачи (участок = неориентированный отрезок; для двусторонней улицы допустимо ехать в любом
   направлении). Стоимость рёбер направленная: учитываются уклон (подъём замедляет и увеличивает расход),
   скорость уборки 15 км/ч, перегона 35 км/ч.
2. Кратчайшие перегоны между релевантными узлами (Dijkstra, scipy).
3. Кластеризация участков по машинам (сбалансированный k-means + венгерский алгоритм по стартовым
   позициям).
4. Построение маршрутов в кластерах (path scanning с несколькими правилами и рандомизацией).
5. Локальный поиск (relocate, flip, swap, 2-opt, or-opt, межмаршрутные обмены) по целевой функции
   `0,5·перегон + 0,3·время + 0,2·топливо` (нормировано на базовый план).
6. Базовый план — «наивный» жадный объезд по ближайшему участку; сравнение показывается диспетчеру.
7. Перепланирование: при поломке, заявке или проблеме водителя берутся оставшиеся участки и текущие
   позиции исправных машин, решатель запускается заново, результат оформляется как предложение
   с разницей по машинам; применяется вручную или автоматически.
