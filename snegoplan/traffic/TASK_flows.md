# Задача: макромодель транспортных потоков → веса рёбер графа

Рабочая папка: `traffic/` (скрипты в `traffic/scripts/`, выход в `traffic/out/`, отчёт `traffic/REPORT.md` по-русски). Windows, Python с `-I`, можно `pip install numpy scipy networkx`. Не трогать файлы вне `traffic/`. Все параметры — в `traffic/params.json` (чтобы потом калибровать без правки кода).

## Вход
- `../mapprep/out/graph_v3.json` — граф (узлы, направленные рёбра: id, u, v, length_m, lanes, maxspeed, highway, zone, traffic_signals на узлах).
- `../mapdata/data/residential.csv`, `../mapdata/data/attractors.csv` — здания и POI.
- (опционально) `../mapdata/data/ksodd_tables/traffic_intensity.csv` — для калибровки, если есть.

## Параметры по умолчанию (в params.json)
- население 160000; м² жилья на человека 25; если нет levels: house=1, apartments=5, residential=3, yes=2;
- машин на 1000 жителей 350; поездок на машину в сутки 2.2 (половина «дом→цель», половина обратно);
- веса притяжения (мест на объект или на 100 м²): work/office 30, industry 20, port 300 на объект, school 1/3 учеников ≈ 50, shop 5, health 40, service 10 — грубо, в отчёте это пометить как оценку;
- профиль выездов по часам (доля суточных поездок): 0–5 ч: 0.5%/ч, 6: 3%, 7: 9%, 8: 10%, 9: 6%, 10–15: 5%/ч, 16: 7%, 17: 10%, 18: 8%, 19: 4%, 20–23: 2%/ч (нормировать до 100%);
- слоты: night = 02–05, morning = 07–09, day = 11–15;
- пропускная способность полосы (авт/ч): trunk/primary 900, secondary 800, tertiary 700, residential/unclassified 500, service/living_street 300; светофорный узел ×0.6 для входящих рёбер;
- свободная скорость = min(maxspeed, 60) × 0.85; задержка светофора 25 с на въезд в узел;
- BPR: t = t0·(1 + 0.15·(V/C)^4).

## Что сделать
1. **Источники.** Жители по зданиям: площадь×этажи, нормировать к населению. Привязать каждое здание и POI к ближайшему узлу графа (KD-tree по метрическим координатам), агрегировать в «зоны спроса» = узлы.
2. **Матрица поездок.** Гравитационная модель: T_ij ∝ P_i·A_j·exp(−β·d_ij), d_ij — время в свободном потоке, β подобрать так, чтобы средняя поездка была 12–15 мин (параметр). Двухсторонняя балансировка (Furness, 10 итераций). Утро: дом→цель; вечер: цель→дом; день: 50/50. Чтобы не взорвать память — агрегировать источники/цели до ≤ 400 кластеров (k-means по узлам с весом).
3. **Распределение.** Для каждого часа слота: итеративное распределение (MSA, 5–10 итераций) кратчайшими путями (Dijkstra от каждого кластера-источника, scipy.sparse.csgraph). Поток V_e авт/ч, время по BPR.
4. **Калибровка (если есть traffic_intensity.csv).** Сопоставить участки по названию улицы со средним потоком рёбер, подобрать один общий множитель, в отчёт — таблица модель/КСОДД. Если файла нет — пропустить, написать в отчёт.
5. **Выход `out/edge_traffic.json`:** `{meta:{params, слоты, дата}, edges:{edge_id: {flow:{night,morning,day} (авт/ч, среднее по слоту), vc:{...}, time_s:{...}, t0_s}}}` — для всех рёбер graph_v3, ключ = edge.id.
6. **Приоритет по потоку:** в тот же файл `flow_rank` ∈ {1,2,3} по суточному потоку (верхние 15% км → 1, следующие 35% → 2, остальное 3). Сам приоритет в графе НЕ менять.
7. **Карта `out/traffic_map.html`** (MapLibre или Leaflet с CDN, данные встроены): рёбра раскрашены по V/C, переключатель слота, толщина по потоку.

## Готово, когда
- edge_traffic.json содержит все edge_id из graph_v3, без NaN;
- REPORT.md: число жителей/машин/поездок в сутки, β и средняя длина поездки, топ-15 улиц по утреннему потоку (имя, авт/ч, V/C), доля км с V/C>0.8 по слотам, время работы скрипта, калибровка или её отсутствие;
- traffic_map.html открывается и выглядит правдоподобно (центр и магистрали загружены, дворы — нет).
