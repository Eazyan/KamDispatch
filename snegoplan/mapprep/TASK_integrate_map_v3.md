# Задача Kimi: собрать версионированный map package v3

## Роль и границы

Ты — исполнитель Kimi через OpenCode. Выполни только эту задачу по карте. Не проводи общее ревью проекта, не трогай алгоритм, backend/frontend, HGS, Git/GitHub и сетевые источники. Перед изменениями прочитай `AGENTS.md`, `WORKLOG.md`, этот файл и актуальные отчёты сопоставления/классификации.

Рабочая директория: корень `snegoplan`.

## Цель

Объединить уже готовые данные graph_v3, классификацию сервисных рёбер и сопоставление КСОДД в отдельный, воспроизводимый map package для дальнейшего планирования. Исходный `mapprep/out/graph_v3.json` оставить неизменным. Не менять смысл приоритетов без доказательств.

## Фактические входы

- `mapprep/out/graph_v3.json`, `mapprep/out/zones_v3.json`.
- `mapprep/out/service_classification.csv` и `mapprep/out/REPORT_service.md`.
- `mapdata/data/ksodd_street_match.csv` (131 строка: категории дорог и полосы; у категорий поле `category` может быть пустым).
- `mapdata/data/ksodd_point_match.csv` (142 строки интенсивности).
- `mapdata/data/traffic_lights_match.csv` (87 строк: 61 КСОДД + 26 OSM).
- `mapdata/data/poi_critical.csv` (208 критичных POI, включая status/дубли).
- `mapdata/REPORT_match.md`.
- `mapprep/TASK_service_classification.md`, `mapdata/TASK_match_ksodd.md`.

Не считать прежний `logs/kimi_integrate_map_v3.txt` логом этой интеграции: сейчас он содержит старый/чужой диагностический вывод. Создать новый уникальный лог для текущего запуска.

## Требования к реализации

1. Создать один воспроизводимый скрипт в `mapprep/prep/` для сборки результатов. Не дублировать/переписывать match/classification алгоритмы.
2. Писать результаты только в `mapprep/out/` с новыми именами, например `map_package_v3.json`, `edge_weights_v3_integrated.csv`, `check_map_v3_integrated.html`, `REPORT_v3_integrated.md`. Перед выбором имён проверь, что файлов нет; не перезаписывай чужие результаты.
3. Интегрированный JSON должен включать исходные узлы/рёбра и зоны, сервисные поля из classification, подтверждённые high-confidence атрибуты КСОДД с происхождением, confidence и rationale. Сохраняй все рёбра и все зоны.
4. Из road_categories не придумывать категорию/приоритет, если значение пусто. Лanes/intensity брать в основной интегрированный слой только при `match=yes` и `confidence=high`; medium/low/unmatched оставлять отдельными полями/строками review, не терять.
5. Светофоры сохранять отдельным слоем/списком с исходным статусом матча и источником. Не приписывать неизвестные циклы/фазы/задержки; пустые значения оставить пустыми. Не снапать недоказанные точки на ребро как точные.
6. Сохранить `ownership=unknown`, пока нет реестра/доказательства владения. Не превращать `municipal_service` из OSM-класса в подтверждённое муниципальное владение.
7. Сохранить исходные веса приоритетов 1/2/3 = 10/3/1, автобусные маршруты и критические подъезды к больницам/клиникам в P1. Не использовать средние/низкие матчи для автоматического повышения приоритета.
8. Отдельно вывести medium/low/unmatched/конфликтные строки в review CSV с причиной; указать все непокрытые сущности и ограничения данных.
9. В QA-карте различимо показать зоны, P1/P2/P3, municipal_service vs nonmunicipal-estimate, high-confidence КСОДД enrichment, critical POI и светофоры. Условные обозначения должны прямо различать подтверждённое и оценочное.

## Acceptance criteria

- Скрипт запускается из корня проекта в текущем Windows/Python окружении одной документированной командой.
- Входы покрыты полностью: число узлов/рёбер не уменьшается, все edge_id уникальны и все рёбра classification найдены ровно один раз; обратные рёбра и зоны сохранены.
- Значимые ограничения проверены машинно: `required_current_stage => municipal_service`; пары рёбер сохраняют согласованные сервисные поля; исходный graph_v3 SHA-256 до/после одинаков; веса 10/3/1; нулевые/пустые циклы не заполняются; source/confidence сохранены для каждого добавленного KSODD значения.
- High-confidence интеграция и review-счётчики согласуются с исходными CSV. Не считать matched со статусом medium/low подтверждённым.
- QA HTML автономен/не требует сети. Если невозможно визуально открыть в этой среде, честно отметить это; сделать структурные проверки встроенных данных/слоёв и синтаксиса скриптов.
- Обновить только свои новые артефакты и `WORKLOG.md`; не менять исходный graph_v3 и старые входы/отчёты. В отчёте — команды запуска, цифры, ограничения и backout.
- Не коммитить и не пушить.
