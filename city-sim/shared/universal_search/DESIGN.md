НЕИЗВЕСТНО: отдельный реальный автобусный реестр/телеметрия и подтверждённый
полный реестр баз и снегоприёмных площадок в проверенных контрактах не найдены.
Типы поддержаны ядром и каноническим адаптером, но реальные записи не выдуманы.
Адрес «Королёва 20» не строится из имени улицы и произвольного числа.

## Сравнение перед реализацией

| Вариант | Оценка для этого поручения |
| --- | --- |
| Python list + fuzzy scan | Минимум кода, но нет постоянного fulltext/spatial индекса и атомарной проекции; отвергнут |
| PostgreSQL FTS + pg_trgm + PostGIS | Хорошее развитие для большого масштаба; потребовало бы PG/расширений для автономного запуска и сблизило бы независимые хранилища; пока не нужно |
| OpenSearch/Elasticsearch | Много возможностей, отдельный сервис и эксплуатация без доказанной необходимости; пока не нужно |
| SQLite FTS5 + R*Tree + словарь/postings | **Выбрано**: стандартный Python, один восстановимый файл, транзакции, текст/координаты, без изменения компонентных баз |

FTS5 предоставляет fulltext и prefix queries, R*Tree — диапазонные spatial queries.
Проверены первичные документы: [FTS5](https://www.sqlite.org/fts5.html),
[R*Tree](https://www.sqlite.org/rtree.html). Опечатки и substring добавляются локальным
словарём, а не LLM или тяжёлым внешним сервисом. Отдельная read model хранит только
поисковую проекцию, не становится новым источником бизнес-истины.

Порядок реализации: контракты → транзакционный индекс → нормализация/кандидаты/
ранжирование → read-only адаптеры → CLI → тесты → реальные офлайн выгрузки.
Для merge выбраны только новые пути `shared/universal_search/` и отдельный
workflow `.github/workflows/universal-search.yml`. Компоненты камер/диспетчеризации
не обязательны для импорта или тестов ядра; их можно смержить в любом порядке.

## Проверка реализации

ФАКТ/РАСЧЁТ, локальный запуск 23.11.2026: реальные файлы извлечены `git show`
из указанных SHA в `/tmp/kamchatka-search-sources`, без сетевых запросов к камерам
и без загрузки PostgreSQL. Извлечённые данные не включаются в коммит поиска.
Источник OpenStreetMap сохраняет ODbL-1.0 в source; перед дальнейшей перепубликацией
выгрузок соблюдать их исходные условия, здесь публикуется только код адаптера.

- Успешно: 3714 OSM сущностей (3537 road_section + 177 street), 29 камер.
- Словарь: 6898 токенов. Создание обеих проекций: около 0.28 s.
- `Королева` и `Кроолева`: по 24 результата, около 7 ms на одиночный локальный
  запуск; `Чехова`: камера с координатой; `Завойко 8`: камера по location note.
- `20`, `автобус 20`, `Королёва 20`: 0 результатов на **реальной** выборке;
  это ограничение имеющихся данных, а не повод добавить фиктивный адрес/автобус.
- `PRAGMA integrity_check`: ok. Это smoke/performance observation, не нагрузочное
  испытание и не гарантия SLA. Точность на внешней размеченной выборке unknown.
- 26 offline тестов поиска + 8 существующих starter-тестов: OK. Все данные
  модульных тестов явно синтетические. CI добавлен отдельно для Python 3.10/3.12;
  локальный запуск не доказывает прохождение удалённого CI.

Дальнейшее расширение: реальный автобусный адаптер после получения контракта,
полная авторизованная проекция событий вместо dashboard window, отдельный реестр
подтверждённых межисточниковых связей; измерение расширенного словаря до смены backend.
