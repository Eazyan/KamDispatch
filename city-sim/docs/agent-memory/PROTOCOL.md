# Конечный цикл работы
Updated: 2026-11-22 · Asia/Kamchatka (UTC+12)

LOAD → CHOOSE → PLAN → IMPLEMENT → TEST → CHECKPOINT → NEXT / BLOCKED / DONE.

1. LOAD: прочитать STATE, HANDOFF, TASKS. Выполнить `git status --short --branch`, `git remote -v`; проверить SHA, несохранённые изменения и параллельную работу. Затем нужную строку INDEX и её источник.
2. CHOOSE: `python3 scripts/agent_memory/memory.py next --track WEATHER` (или DRIFT/GRAPH/OPS). Без трека продолжить единственную in_progress; иначе наименьший P/ID среди доступных. При неоднозначности сообщить её, не переключать трек молча. Предупреждение stale сначала разобрать; план из файла не равен актуальному Git.
3. PLAN: один конечный результат, пути и критерий готовности. Не расширять разрешения на API, рассылку, публикацию.
4. IMPLEMENT и TEST: не трогать чужие изменения, до трёх попыток одинаковой ошибки. После третьей — blocker и точная следующая проверка. Отсутствие научных меток — unknown, а не плохой/хороший прогноз.
5. CHECKPOINT: обновить фактические STATE/TASKS/HANDOFF, добавить строку LOG (не переписывать предыдущие записи); значимое знание с источником внести в навигатор. Затем `python3 scripts/agent_memory/memory.py checkpoint`, `python3 scripts/agent_memory/verify.py`. Если после snapshot снова менялись файлы, повторить checkpoint. Команда checkpoint только фиксирует metadata и не пишет выводы вместо агента.
6. NEXT только при независимости, времени и успешных тестах. BLOCKED — записать условие разблокировки. DONE — handoff и остановка. Нет фоновых циклов и автоматических Stop retries.

Переход: новая сессия читает 3 коротких файла → проверяет checkout → выбирает доступную задачу → читает её источник → делает конечную итерацию → сохраняет checkpoint → следующая сессия повторяет вход.

Для нового агента достаточно: «Продолжи WEATHER», «Продолжи ночные погодные алерты», «Продолжи карту снежных наносов» либо «Продолжай работу». Новая сессия должна быть открыта в том же checkout; наличие файлов не даёт доступа к другому чату.
