# Журнал разработки обращений жителей

## 22 ноября 2026 · первый API

- Репозиторий `Eazyan/KamDispatch` склонирован в текущий каталог. Работа начата на ветке `Citizens`, исходный коммит `9cf90e4`. Первая попытка клонирования завершилась сетевой ошибкой в песочнице. Повтор с разрешением прошёл.
- API добавлен в существующее приложение `monitoring/api.py`. Маршруты и обработка фото находятся в `monitoring/citizens.py`. Миграция `011_citizen_reports.sql` сохраняет фото в PostgreSQL вместе с обращением, чтобы исключить частичную запись при сбое. Выборка использует индекс по режиму, району и времени.
- По уточнению заказчика форма принимает координаты; район вычисляет сервер по GeoJSON. Справочник загружается при старте в `monitoring/districts.py`. При отсутствии покрытия точка сохраняется с `district_id=unassigned`. Границы для рабочего развёртывания требуют подтверждённого набора данных. Фигуры в тестах синтетические.
- Ручные теги и будущие рекомендации модели хранятся в отдельных полях `tags` и `suggested_tags`. При подключении классификатора он должен обновлять `suggested_tags`, сохраняя выбор автора.
- Создание обращения в режиме `live` использует существующий OIDC. В журнал приложения попадает UUID сохранённого обращения и режим. Текст, координаты, токены и содержимое фото в эту запись не входят.
- Контракт, примеры и настройка границ описаны в [API обращений](CITIZENS_API.md). Проверки маршрутов находятся в `tests/test_citizens.py`. Для проверки PostgreSQL задайте `TEST_DATABASE_URL` на временную базу и выполните `python -m pytest`.
- Полный набор Python-тестов с временным PostgreSQL 17.5 прошёл, 35 тестов. Проверены сохранение и повторное чтение фото, вычисление района на границе и вне покрытия, фильтр периода, пагинация и изоляция режимов. Starlette выдала одно предупреждение об устаревшем псевдониме AnyIO. `git diff --check` прошёл.
- Временный PostgreSQL остановлен после проверки. Первый запрос на запись в `.git` отклонён. По следующему указанию пользователя изменения разбиты по смыслу для локальных коммитов в `Citizens`: реализация с тестами и документация с журналом.

## 22 ноября 2026 · единый сервис для формы и Telegram

- Индекс проекта. `monitoring/api.py` обслуживает API и статику. `monitoring/citizens.py` содержит маршруты, обработку фото и операции с обращениями. `monitoring/migrations/` обновляет PostgreSQL при старте. Панель диспетчера собирается из `web/`, форма жителей обслуживается из `resident_site/` по адресу `/citizens/`. `compose.yaml` и `bootstrap.sh` поднимают базу, API, обработчик мониторинга и бота.
- Из `../bot` перенесены интерфейс с Leaflet, поиск по адресу, предпросмотр фото, диалог Telegram, просмотр личной истории, сводка зон и словарь зимних тегов. Бот `monitoring/citizen_bot.py` отправляет файл в API и читает историю и фото через API. Черновики остаются в памяти бота до отправки. Во время работы у формы и бота нет зависимости от SQLite.
- Миграция `012` добавила адрес, предотвращение дублей по UUID запроса в рамках автора и режима, индекс истории. Автоматические теги хранятся отдельно от ручных. Для Telegram используется внутренний ключ; для браузера в `live` сохранена действующая схема OIDC. Сводка зон в `live` доступна сотрудникам. У формы и бота общий лимит загрузки 5 МиБ.
- Исходная папка и SQLite сохранены. Прежние процессы не обнаружены. Исходный SQLite содержит четыре записи, из них три со ссылкой на фото Telegram. `monitoring/citizen_import.py` читает снимок в режиме read-only, сохраняет фото и исходное время в PostgreSQL и пропускает уже перенесённые записи при повторном запуске. Сам снимок пока не переносили. Для получения ранее загруженных фото нужен токен исходного бота и должен быть выбран режим назначения.
- `./bootstrap.sh` создаёт ключ бота в локальной конфигурации, ожидает готовности API и печатает адрес формы. Без `BOT_TOKEN` контейнер бота завершает запуск штатно. Порядок запуска и переноса описан в README.
- Проверки. На чистом PostgreSQL 16 прошли 38 Python-тестов, включая изоляцию истории, повтор запросов, откат импорта и обмен бота с API на подставном Telegram. Сборка и запуск через `./bootstrap.sh` прошли. `/citizens/` ответил HTTP 200, `/healthz` вернул `ready`. `git diff --check`, проверка Bash и синтаксиса JavaScript прошли. Подключение реального Telegram и перенос исходной базы остаются после настройки `BOT_TOKEN`.
- Веб-тесты панели прошли, 8 тестов. Временный контейнер PostgreSQL остановлен. Локальный стек оставлен запущенным.

## 22 ноября 2026 · определение района по координатам

- Штатный справочник содержит границы 14 муниципальных районов и городских округов Камчатского края. Геометрия взята из снимка OpenStreetMap, версия `5af46d6dab9a502713611846892e4185f157dab7` репозитория `timurkanaz/Russia_geojson_OSM`. Полигоны сохранены без упрощения, им присвоены стабильные идентификаторы. Источник и лицензия ODbL указаны в GeoJSON и контракте. Для замены можно задать `CITIZEN_DISTRICTS_FILE`.
- API вычисляет район локально при записи обращения с сайта, из Telegram и при импорте SQLite. При запуске API пересчитывает записи текущего режима, у которых район ещё не определён. За пределами покрытия остаётся `unassigned`. Справочник описывает муниципальные границы, без деления на городские микрорайоны. Для задач, где нужны юридически точные границы, потребуется официальный кадастровый слой.
- На чистом PostgreSQL 16 прошли 44 теста. Проверены точки в Петропавловске-Камчатском, Елизове, Вилючинске, Палане, Никольском и за пределами края, а также пересчёт существующей записи при старте и сохранение `unassigned` вне покрытия. `git diff --check` прошёл.
- Локальный стек обновлён через `./bootstrap.sh`. Запущенный API вернул 14 муниципалитетов и вариант «Район не определён». Временная база проверки остановлена.
