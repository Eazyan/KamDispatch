## Два уровня

1. `city-sim/city_sim/drift_engine.py`: консервативный SnowState + ограниченная
   направленная поправка скорости по уклону DSM и сценарной снежной поверхности.
   Это исследовательская параметризация ветра, НЕ WindNinja и НЕ CFD.
2. `cfd/run_cfd.py`: отдельный настоящий OpenFOAM simpleFoam RANS воздуха над кварталом,
   с рельефом и зданиями. Нет связанного CFD-снегопереноса и динамического снежного mesh.
   Результаты воздуха не подменяют снегоперенос и не загружаются молча в быстрый режим.

API `POST /api/v1/drift-engine/compare` ограничивает сетку 16/32/64, 1 час сценария,
скорость 40 м/с. Работает по сохранённым геоданным, не делает погодных запросов.
Возвращает оба массовых поля, ledger, solver/version, входной SHA256, время, provenance,
`research_unvalidated`, а подробный CFD-снег — `not_connected`. `legacy_dynamic` обозначает
SnowState, не эмпирическую карту CitySnow. Прежняя карта и API сохранены.
Экран `/drift-engine` использует общую шкалу кг/м² и сообщает границы доказательности.

## Воспроизведение

```bash
cd city-sim
python -m venv .venv
.venv/bin/pip install -r requirements-core.txt -r requirements-city-sim.txt
.venv/bin/python -m city_sim.reproduce_drift_engine --output ../out/drift-engine
.venv/bin/python -m city_sim
# http://127.0.0.1:8008/drift-engine
curl -H 'Content-Type: application/json' -d '{"resolution":32}' http://127.0.0.1:8008/api/v1/drift-engine/compare
```

Полные регрессии прежнего режима требуют закреплённого движка Данила;
его установка есть в `.github/workflows/drift-engine.yml` и README_CITY_SIM.
Запуск API нового режима не требует внешнего CFD. Точные команды CFD — SOLVER_AUDIT.
Следующее: полноценное поле ветра, единая сцена с DTM и высотами зданий,
связанный CFD-снег, независимые измерения. Никакой фоновой работы не настроено.

## 22.11.2026: явное поле сохранённого RANS

`city_sim.cfd_wind` читает `cfd/results/dec-snow-coarse/wind.npz` и связывает
его с SnowState на точной подвыборке исходной сетки 49×48. Пересэмплирования на
прежний городской экран нет: там другая область, поэтому HTTP сравнение сохраняет
прежний slope baseline. Новый путь доступен offline; тяжёлые решатели из HTTP не вызываются.

Контракт `run(..., wind_field=...)`: конечные массивы `vector_east_south_m_s`
(shape rows×cols×2), `height_agl_m` (rows×cols) и JSON provenance. Поле заменяет
уклонную экспозицию, не умножается на неё. Компоненты скорости сохраняют локальные
повороты/рециркуляцию; перенос ограничен доступной массой каждого донора, каждый
внутренний перевод списывается/начисляется одной величиной kg. Открытые границы
также учитывают локальное направление. Для u* используется прежнее log-law замыкание
с фактической номинальной высотой первого слоя вместо молчаливого предположения 10 m.
Это исследовательское замыкание, не разрешённая CFD сальтация/взвесь.

Оси исходного CFD: x east, y north, U m/s. Адаптер разворачивает порядок строк и
меняет знак Uy. Координаты — локальная сферическая проекция из quarter.json,
origin southwest WGS84, metres/degree из источника; это НЕ EPSG:32657. Границы
транспортной области проходят по граням выбранных ячеек, а не точно по bbox квартала.
Первый terrain-following слой: nominal centre AGL = (top-ground)×mean(z_edges[0:2]),
0.778–1.151 m; маска зданий взята из той же CFD сцены. Отсутствующая скорость на
открытом грунте вызывает ошибку, а не заменяется нулём или скоростью над крышей.

Ветер статичен: снег не меняет CFD геометрию и не запускает новый расчёт воздуха.
Версия reduced 0.2 хеширует компоненты, высоту, provenance и входы; хеши исходных
quarter.json, wind.npz и summary.json включены в результат. Метаданные SnowState
по умолчанию описывают UTM домен, поэтому адаптер их не экспортирует: его локальная
сцена описана отдельным provenance. Измеренный DTM и точность остаются unknown.

Воспроизведение из city-sim:
`python -m city_sim.cfd_wind --output ../out/drift-engine/cfd-coupling.json`.
CFD повторно не решается: используется уже проверенный результат 360 итераций v2512.
