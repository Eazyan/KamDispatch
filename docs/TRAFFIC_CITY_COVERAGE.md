# Городской сбор: готовность и ограничения

23 ноября 2026, Asia/Kamchatka. База перед изменениями: `e70d551`.
Цель пользователя: охватить снимками всю территорию города и явно показывать
пропуски данных. Затем пользователь остановил полный сбор и разрешил только
проверки устойчивости и независимое ревью. **Полный живой прогон не выполнен.**

## Периметр

Граница — [OSM relation 4139922](https://www.openstreetmap.org/relation/4139922),
версия 29, сверенная с текущим OSM 23 ноября. В примечании источника граница города
условно совпадает с городским округом; это не проверка официальных границ.
Используется весь исходный набор `monitoring/snow_roads.json.gz`: 7 806 автомобильных
участков. У набора не указан timestamp источника; полнота реальных дорог в OSM
не доказана. Граница и дорожный снимок фиксируются SHA256 в плане.

План строится по всей Polygon/MultiPolygon, включая окраины, с перекрытием кадров.
Для пригодного исходного кадра 4096×4096 CSS px при zoom 16 получилось 29 новых
видов плюс повторно используемый исходный — 30. Число зависит от положения сетки.
Офлайн-проекция плана покрывает всю границу и полную геометрию всех 7 806 участков.
Концы дорог не обрезаются для получения удобного знаменателя.

## Что проверено без полного сбора

- Синтетический цикл 30 видов с fake transport, без запросов к 2ГИС: завершение,
  один временный сбой и ограниченный повтор, повторный запуск без пересъёмки готового.
- Семь ранее сохранённых живых пар повторно проверены по PNG/SHA, четвёртой точке,
  фактическому центру и масштабу. Они покрывают около 25,69% границы и полностью
  5 047 участков; это **частичный результат**, не весь город.
- Реальный полный прогон остановлен на 7/30. Незавершённая следующая пара сохранена.
  Атомарная публикация и новые сценарии восстановления проверены офлайн, не полной
  повторной съёмкой города.
- Подробный протокол: [traffic-citywide-readiness-2026-11-23.json](traffic-citywide-readiness-2026-11-23.json).

## Состояния и восстановление

| Сценарий | Поведение |
| --- | --- |
| Готовая пара | Проверяются PNG, калибровка, план и качество; повторного запроса нет |
| Прерывание посреди кадра | Неполная попытка сохранена, но не опубликована и не засчитана |
| Старый неполный каталог | Архивируется в `attempts/`; при следующем явном запуске переснимается только этот вид |
| Пара запечатана до ошибки закрытия Chrome | Восстанавливается из попытки без нового запроса |
| Таймаут основного перехода или HTTP 5xx | Не более двух попыток вида, между ними две секунды |
| 403, 429, CAPTCHA | Остановка `blocked`, без автоматического повтора или обхода |
| Таймаут кнопки/меню, ошибка калибровки, качества | Остановка, без автоматического повтора |
| Ctrl-C | Статус `interrupted`, следующие виды не запускаются; OS-lock освобождается |
| Второй сборщик | Отклоняется OS-lock до обращения к браузеру |
| Ошибка публикации файла | Атомарная замена сохраняет прежний целый файл |
| Изменена калибровка/ROI или испорчен HTML | Кэш не используется; анализ восстанавливается офлайн |
| Карта не переместилась или изменила zoom | Выявляется по UI-калибровке, кадр не публикуется |

Пара сначала создаётся в уникальной папке попытки. Только после проверки она
атомарно перемещается в `captures/ID`. Это позволяет продолжиться после падения
между сохранением PNG и обновлением статуса. При SIGKILL статус может остаться
старым: при продолжении истинным источником являются повторно проверенные файлы,
а не слово `running`/`complete`. Повтор после блокировки возможен только новым
явным запуском оператора; программа не решает CAPTCHA и не обходит ограничение.

Применение `capture-city` успешно завершает фазу съёмки, но географическое покрытие
подтверждает отдельный `analyze-city --require-full`. При недостатке кадров команда
сохраняет карту пропусков и завершается с ошибкой. Проверяется фактическое объединение
калиброванных областей, вся граница и полная длина каждой исходной дороги.

## Почему кадры проверяются отдельно

В старом `pilot-2` reference PNG оказался одноцветным placeholder. Его прежние
метрики парного распознавания недостоверны. Этот вход теперь отклоняется;
исторические отчёты сохранены. На `pilot-4`, использованном для 170/184, этот
дефект не воспроизведён. Обычное ожидание DOM или network idle не доказывает
загрузку карты. Поэтому проверяются сами PNG, изменившиеся нетрафиковые области
и блоки изображения. Малодетальные области показываются отдельно; их нельзя
выдавать за наблюдение свободной дороги.

Chrome работает в отдельном временном профиле с DPR=1. Уменьшенные снимки для
непрерывного pixel-stability контроля на больших Retina-кадрах вызывали лишнюю
перерисовку и не давали стабильного завершения; этот эксперимент удалён. Используется
ожидание ресурсов/отрисовки с обязательной проверкой сохранённой пары. Доступность
2ГИС, неизменность его интерфейса и наличие трафика на каждой дороге не гарантированы.
Нет данных — unknown, а не free. Снимки последовательны, возможны временные
расхождения; конфликтующие классы не объединяются в один достоверный сигнал.

## Команды для будущего явного запуска

Это инструкция, не свидетельство выполнения полного прогона:

```bash
python scripts/capture_traffic.py capture out/seed --center 158.65 53.04 --viewport 4096 4096
python scripts/capture_traffic.py plan-city out/city --boundary city-boundary.geojson --seed out/seed
python scripts/capture_traffic.py capture-city out/city
python scripts/capture_traffic.py analyze-city out/city --require-full
```

Готовые кадры при повторном `capture-city` сохраняются. Не запускайте второй сборщик
на тот же каталог. Исходные PNG не включаются в PR. Автоматическая передача данных
в диспетчерские задания и маршрутизатор не добавлялась.
