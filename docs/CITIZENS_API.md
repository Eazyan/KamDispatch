# API обращений жителей

FastAPI принимает обращения на том же адресе, что и API мониторинга. Миграция `011_citizen_reports.sql` применяется при запуске. Фотография, текст, координаты и теги сохраняются в PostgreSQL одной транзакцией.

## Приём обращения

`POST /api/v1/citizens/reports` принимает `multipart/form-data`.

| Поле | Формат |
| --- | --- |
| `photo` | Необязательно. Один JPEG или PNG до 5 МиБ и 16 мегапикселей. Для запросов от бота MAX также доступны WebP и AVIF. API сохраняет JPEG без метаданных с длинной стороной до 2048 пикселей. |
| `description` | Текст от 1 до 2000 символов. |
| `latitude` | Широта WGS84 от −90 до 90. |
| `longitude` | Долгота WGS84 от −180 до 180. |
| `tags` | До четырёх необязательных повторяющихся полей. Допустимы `снег`, `дождь`, `пробка`, `сугроб`. Дубликаты удаляются. |

Клиент получает координаты из геолокации устройства, выбранной точки или результата геокодирования вручную введённого адреса. Пользователь может проверить найденную точку на карте перед отправкой. Сервер определяет район по координатам.

`GET /api/v1/citizens/address-search?q=...` ищет адреса в публичном городском каталоге Петропавловска-Камчатского. Возвращает до пяти записей `matches` с полями `address`, `latitude` и `longitude`. `local: true` означает, что каталог распознал местный запрос: пустой список сообщает об отсутствии точки для номера дома. Форма использует Photon для запросов, которые городской каталог не распознал. [Источник и версия адресов](../monitoring/data/README.md)

```bash
curl -F photo=@snow.jpg \
  -F 'description=Сугроб закрывает проход' \
  -F latitude=53.02 -F longitude=158.65 \
  -F tags=снег -F tags=сугроб \
  http://localhost:8080/api/v1/citizens/reports
```

Успешный ответ имеет статус `201` и содержит поля `id`, `report_number`, `description`, `latitude`, `longitude`, `district_id`, `district`, `tags`, `suggested_tags`, `created_at` и `photo_url`. Поле `suggested_tags` содержит автоматически определённые зимние теги. Без фото `photo_url` равен `null`. Повторная отправка с тем же `request_id` возвращает исходную запись. При 30 новых обращениях за час для одного отправителя API возвращает `429`. Новое обращение появляется в диспетчерской и на карте в своём режиме. Некорректные поля дают `422`, превышение лимита загрузки даёт `413`, неподдерживаемое или повреждённое фото даёт `415`.

`report_number` — положительный порядковый номер, начиная с 1 для каждого автора в каждом режиме. Повтор с тем же `request_id` возвращает прежний номер. При обновлении базы ранее сохранённые обращения получают номера по возрастанию `created_at`, при равенстве — по UUID. Поле `id` сохраняет UUID записи и используется в глобальных ссылках, фильтрах и адресах фото.

## Чтение

| Маршрут | Ответ |
| --- | --- |
| `GET /api/v1/citizens/districts` | Массив вариантов фильтра с полями `id` и `name`. Для микрорайонов передаётся `parent_id` городского округа. |
| `GET /api/v1/citizens/reports` | Обращения с полями как у ответа `201`. Необязательные фильтры: `district` (идентификатор), `start` и `end` (ISO 8601 со смещением или `Z`), `id` (UUID записи). Без фильтров возвращаются последние обращения по всем районам. Период применяется к времени создания, начало включается, конец исключается. Новые записи идут первыми. |
| `GET /api/v1/citizens/reports/{id}/photo` | Сохранённое фото с типом `image/jpeg`. |

Список возвращается как `{"items":[...],"next_offset":null}`. Передайте `limit` от 1 до 100 (по умолчанию 50) и `offset` (по умолчанию 0). Для следующей страницы передайте значение `next_offset`, если оно задано.

```bash
curl --get http://localhost:8080/api/v1/citizens/reports \
  --data-urlencode district=unassigned \
  --data-urlencode 'start=2026-11-22T00:00:00+12:00' \
  --data-urlencode 'end=2026-11-23T00:00:00+12:00'
```

В режиме `live` передавайте `Authorization: Bearer <OIDC token>`. Создать обращение может любой пользователь с действительным токеном приложения. Список районов и обращений доступен операторам и наблюдателям. Фото доступно также автору, а для остальных запрос возвращает `404`. Локальные режимы работают без токена. Обращения из разных режимов изолированы.

В панели мониторинга вкладка «Обращения жителей» показывает поступившие записи, фильтры по району и датам, адрес, координаты, теги и фото. Даты фильтра относятся к часовому поясу Камчатки. На главном экране «Обстановка» последние три обращения с сайта, из Telegram и MAX отображаются в правом виджете и отмечены точками на обзорной карте в режиме «Данные сервиса». Данные обновляются каждые 10 секунд. Нажатие на точку открывает карточку обращения. В `live` действует доступ оператора или наблюдателя.

## Границы районов

По умолчанию API определяет муниципальный район или городской округ по локальному GeoJSON с 14 муниципалитетами Камчатского края. Это снимок границ OpenStreetMap, а не кадастровый набор. Для вычисления района используется попадание координат в полигон, включая границу. Координаты из обращений обрабатываются на сервере. Внешние запросы для определения района не нужны. [Снимок исходных данных](https://github.com/timurkanaz/Russia_geojson_OSM/tree/5af46d6dab9a502713611846892e4185f157dab7) · [© OpenStreetMap contributors, ODbL](https://www.openstreetmap.org/copyright).

В Петропавловске-Камчатском дополнительно выделены 37 микрорайонов и местностей, в том числе Центр, Сероглазка, Северо-Восток, Силуэт, Горизонт-Север, Горизонт-Юг и Завойко. Точка в размеченном контуре получает название этого микрорайона. Для объектов, отмеченных только точкой, применяется ближайший ориентир в радиусе 900 м. Для Центра ориентиром служит площадь Ленина, для Северо-Востока — участок между улицами Ларина, Савченко и Дальневосточной. Это приблизительная привязка. Точки городского округа без совпадения сохраняют название округа. Фильтр `district=petropavlovsk-kamchatsky` показывает весь городской округ, а `district=pk-seroglazka` — только Сероглазку. [Снимок OpenStreetMap от 21.11.2026](https://download.openstreetmap.fr/extracts/russia/far_eastern_federal_district/) · [Планировочные названия в генеральном плане](https://base.garant.ru/73375673/53f89421bbdaf741eb2d1ecc4ddb4c33/).

Чтобы заменить справочник в Docker Compose, положите GeoJSON в `runtime/citizens/districts.geojson` и задайте в `.env` значение `CITIZEN_DISTRICTS_FILE=/app/runtime/citizens/districts.geojson`. При запуске без Compose укажите путь к файлу в переменной окружения. Файл должен содержать `FeatureCollection` с геометриями `Polygon` или `MultiPolygon` в WGS84. Порядок осей в GeoJSON — `[долгота, широта]`. Для каждого объекта задайте `properties.id` (уникальный стабильный идентификатор из строчных латинских букв, цифр и дефисов) и `properties.name` (название для интерфейса). На общей границе выбирается первый подходящий объект в порядке файла.

Справочник загружается при запуске и применяется к новым обращениям с сайта, из Telegram и из MAX. При запуске API определяет район для записей текущего режима с `district_id=unassigned` и уточняет до микрорайона записи, ранее отнесённые ко всему Петропавловск-Камчатскому городскому округу. Уже назначенные микрорайоны и остальные районы сохраняются. Если точка находится вне покрытия, сохраняются `district_id=unassigned` и `district=null`. Такие записи доступны через фильтр `district=unassigned`. Значение `unassigned` зарезервировано.

## Бот и сайт

Форма доступна по адресу `/citizens/` на том же сервере. Она поддерживает загрузку фото, предпросмотр, геолокацию, выбор точки на карте и поиск адреса. В режиме `live` форма запрашивает токен доступа OIDC, полученный во внешней системе входа. Значение передаётся только в заголовке API и не сохраняется в браузерном хранилище.

Два дополнительных поля при отправке необязательны. `address` хранит подпись адреса до 240 символов. `request_id` принимает UUID. Повтор с тем же UUID, автором и режимом возвращает исходное обращение со статусом `201`. Словарь из предыдущей версии заполняет `suggested_tags` при сохранении. Ручные теги остаются в `tags`.

Боты передают `X-Citizen-Bot-Key` с внутренним ключом и один заголовок с ID автора приватного сообщения: `X-Telegram-User` для Telegram или `X-Max-User` для MAX. Для авторов используются отдельные пространства идентификаторов `telegram:` и `max:`. Оба бота скачивают фото из своего мессенджера, передают его как multipart и получают подтверждённые обращения и фото из API. В личном диалоге доступны `/my`, `/report 1` и `/description 1`. Ранее выданные команды по UUID и ссылки пагинации продолжают работать.

После фото и описания в Telegram и MAX можно отправить геометку или написать улицу и номер дома в Петропавловске-Камчатском, например «улица Ларина, 22». Боты используют городской каталог OpenStreetMap, допускают опечатки в названии улицы и требуют совпадения номера дома. Найденный адрес и его координаты сохраняются после подтверждения. Если совпадений нет или их несколько, можно уточнить адрес или отправить геометку. [© OpenStreetMap contributors, ODbL](https://www.openstreetmap.org/copyright).

Форма без входа передаёт `X-Citizen-Browser-Id` с UUID, сохранённым в браузере. В таких режимах последовательность относится к профилю браузера и начинается заново после очистки его данных. Ранее созданные анонимные обращения и запросы без этого заголовка принадлежат общей последовательности локального автора. В режиме `live` автор формы определяется по OIDC.

| Маршрут | Ответ |
| --- | --- |
| `GET /api/v1/citizens/reports/mine` | Массив обращений автора. Можно указать `limit` (по умолчанию 5) и `before` (UUID последней записи предыдущей страницы). Требуется Telegram, MAX или OIDC. |
| `GET /api/v1/citizens/reports/{id}` | Обращение автора по UUID или личному номеру. Требуется Telegram, MAX или OIDC. |
| `GET /api/v1/citizens/reports/zones?minimum=2` | Ячейки сетки 0,01° текущего режима с полями `latitude_cell`, `longitude_cell`, `count`. Чтобы получить нижнюю границу ячейки, разделите индексы на 100. В режиме `live` требуется доступ оператора или наблюдателя. |

## Задания и прогнозы в ботах

Внутренние маршруты `/api/v1/bot-dispatch` используют заголовок ключа бота и ID пользователя из Telegram или MAX. Привязки ролей задаются на сервере через `DISPATCH_BOT_CREWS`, `DISPATCH_TELEGRAM_ADMINS` и `DISPATCH_MAX_OPERATORS`. При отсутствии привязки действует роль жителя. Новые обращения с сайта, из Telegram и MAX автоматически регистрируются в диспетчерской своего режима с тем же UUID. Повтор отправки сохраняет одну запись в очереди.

| Маршрут | Назначение |
| --- | --- |
| `GET /role` | Возвращает активную роль аккаунта. Для подрядчика или диспетчера MAX также возвращает `assigned_role`. |
| `PUT /role` | Принимает поле `role`. Аккаунт MAX с назначением может выбрать роль жителя или вернуться к назначению. Выбор сохраняется для текущего режима сервиса. |
| `GET /tasks?offset=0` | Подрядчик получает свободные задания своей бригады и лично закреплённые за ним задания. Диспетчер MAX получает задания на этапах принятия и проверки выполнения. |
| `PUT /tasks/{id}` | Принимает `version`, `action` и `note`. Подрядчик выполняет `accept` и `start`. Первое принятие закрепляет задание за аккаунтом. Диспетчер MAX может выполнить `accept` и `close`. Для закрытия требуется комментарий. |
| `POST /tasks/{id}/result` | Закреплённый подрядчик передаёт результат как multipart с полями `version`, `note` и `photo`. Фото обязательно и сохраняется как JPEG. |
| `GET /tasks/{id}/result-photo` | Возвращает первый JPEG текущего результата для диспетчера MAX. Маршрут веб-диспетчерской `GET /api/v1/dispatch/tasks/{id}/result-photo` также возвращает первое фото, а карточка задания показывает все фотографии результата. |
| `GET /task-notices` | Возвращает назначения бригады без отметки о доставке и уведомления о доработке с причиной только для закреплённого исполнителя. |
| `PUT /task-notices/receipt` | Запоминает доставленное уведомление для получателя по `run_id`, `task_id` и `version`. |
| `GET /warnings?pending=true` | Возвращает действующие предупреждения для администратора Telegram. Параметр `pending` оставляет версии без отметки о доставке этому получателю. |
| `PUT /warnings/receipt` | Запоминает указанные `run_id`, `point` и `revision` для авторизованного получателя после ответа Telegram об успешной отправке. |
