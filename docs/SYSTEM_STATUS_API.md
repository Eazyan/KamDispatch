# Состояние компонентов ЦУП

`GET /api/v1/status` возвращает HTTP 200 и снимок состояния. Код HTTP обозначает успешное получение снимка. Состояние системы находится в поле `status`. Эндпоинт не выполняет SQL, авторизацию или внешние запросы при чтении. В нём нет секретов, персональных данных и внутренних адресов. Ответ содержит `Cache-Control: private, no-store`.

```json
{
  "status": "degraded",
  "checked_at": "2026-11-24T05:00:05Z",
  "components": {
    "worker": {
      "status": "stale",
      "last_success_at": "2026-11-24T04:58:30Z",
      "checked_at": "2026-11-24T04:58:30Z",
      "age_seconds": 95,
      "valid_until": "2026-11-24T05:00:00Z",
      "reason": "heartbeat_expired"
    }
  }
}
```

| Поле | Семантика |
| --- | --- |
| `status` | `healthy` — последняя проверка успешна. `degraded` — доступны прежние данные или часть подсистем. `stale` — срок истёк. `unavailable` — работа недоступна. `unknown` — нет сведений, компонент отключён или зависимость мешает установить состояние. |
| `last_success_at`, `checked_at` | Последнее подтверждённое обновление и время последней проверки соответственно. UTC с часовым поясом или null. HTTP-успех источника пробок относится к приёму публикации; время наблюдения указано для каждого интервала. |
| `age_seconds` | Возраст с момента последнего подтверждённого обновления на момент проверки. Фронтенд может пересчитать возраст по timestamp. |
| `valid_until` | Абсолютный срок годности. При `now >= valid_until` интервал просрочен. Null означает отсутствие известного срока. |
| `reason` | Машиночитаемый код или null. Примеры: `heartbeat_expired`, `database_unavailable`, `upstream_http_503`, `upstream_timeout`, `invalid_payload`, `expired_payload`, `some_intervals_expired`, `positions_expired`, `status_snapshot_expired`. Клиент должен принимать неизвестные коды. |

Компоненты `postgresql`, `worker`, `weather`, `traffic`, `buses`, `city_sim`, `citizens`, `dispatch`. Check для обращений и заданий отражает доступность базы для соответствующего API. Доставка внешнему получателю отдельная операция. City Sim сообщает доступность рельефа и снежного решателя. Worker пишет heartbeat каждые 30 с. Порог по умолчанию 90 с, настраивается через `WORKER_HEARTBEAT_TTL_SECONDS`. Плановый опрос статусов — каждые 5 с после завершения предыдущего. Снимок старше 20 с возвращает `unknown` до обновления. Отключённые источники не понижают общий статус. Смешанное состояние активных компонентов даёт `degraded`.

## Погода

`GET /api/v1/dashboard` сохраняет существующий массив `forecasts` и добавляет объект `weather_source` с картой `points`, ключи которой совпадают с `forecasts[].point`. Такой же объект доступен в `components.weather`. При 503, неверном ответе и полностью просроченном наборе текущий прогноз сохраняется. Пока кеш действителен, источник имеет `degraded`. После истечения он имеет `stale`. При отсутствии успешной загрузки ошибка даёт `unavailable`. Для каждого пункта срок равен более ранней из дат: дата загрузки плюс `WEATHER_TTL_SECONDS` (3600 с по умолчанию) и конец последнего прогнозного интервала. Объект содержит причину и время попытки. Для OpenWeather, который не передаёт проверяемое время выпуска для каждого ответа, время успешного получения не гарантирует обновление модели поставщика.

## Пробки

`GET /api/v1/traffic` сохраняет поля публикации и добавляет `source` с последним успешным получением, последней попыткой и причиной отказа. У каждого элемента `segments[]` поля `corridor_id`, `coordinates`, `observed_at`, `valid_until`, `status`, необязательное `estimated`. Статусы интервалов — `free`, `slow`, `congested`, `stale`. Для `stale` frontend может использовать серую линию. Срок считается от наблюдения, `TRAFFIC_TTL_SECONDS=3600` по умолчанию. Расчётный интервал наследует более раннее из двух времён наблюдения. Непокрытые интервалы, включая разрывы между наблюдениями свободного движения, не выдаются как `free`. Отсутствие записи означает неизвестное состояние дороги. Прежний корневой `valid_until` остаётся ближайшим сроком среди интервалов. Для покраски каждого участка используйте его собственное поле. Состояние `complete` означает полноту публикации источника, уличное покрытие задаётся списком интервалов.

При временном отказе источника API может вернуть прежнюю совместимую публикацию с ненулевым `source.reason`. Классификация просрочки пересчитывается при каждом запросе. Без успешной публикации сбой даёт HTTP 503. Если источник вернул отсутствие наблюдений, результат может быть null или публикацией с пустым списком.

## База и шлюз

`/healthz` и маршруты, которым нужна недоступная PostgreSQL, возвращают HTTP 503 с `Retry-After: 5`, кодом `database_unavailable` и `status_url`. Статика, City Sim, пробки и `/api/v1/status` могут обслуживаться независимо от базы. Маршрут состояния нужно направлять на API мониторинга. В установках с публичным фильтром панели запускайте `uvicorn monitoring.public_dashboard:app --host 0.0.0.0 --port 8090`. Задайте внутренний `PUBLIC_DASHBOARD_UPSTREAM` и существующий `CITY_MAP_URL`, затем направьте только публичный `/api/v1/dashboard` на этот процесс. Он пропускает погодный статус и сохраняет 503 при недоступной базе. Закрытый диспетчерский маршрут по-прежнему направляется на основной API.
